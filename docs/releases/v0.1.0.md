# OpsNow v0.1.0 — Initial Portfolio Release

First tagged checkpoint of OpsNow, a full-stack IT Service Management
platform built to demonstrate production-quality engineering practice: a
React SPA, a versioned NestJS REST API, and PostgreSQL via Prisma, with
every phase built, tested and independently reviewed before being marked
complete.

**This is a portfolio checkpoint, not a production release.** OpsNow has
never been deployed anywhere — no hosting account, managed database,
registry, domain or credential exists. See "What's not included" below.

## Highlights

- **Ticket management** — full lifecycle (create, assign, transition
  through an explicit state machine, comment, reopen), with row-level
  visibility so an employee sees only their own tickets while staff see
  all, enforced on the backend.
- **SLA management** — per-ticket response/resolution clocks snapshotted
  from policy at creation, pause/resume on hold, breach/at-risk
  detection, and a staff dashboard — all backend-authoritative, never
  re-derived in the browser.
- **Asset management** — inventory, assignment (a single seam with a
  compare-and-swap concurrency guard), a full assignment ledger, and
  ticket↔asset linking.
- **Knowledge base** — authoring, categorisation, PostgreSQL full-text
  search, and article feedback.
- **Dashboard & analytics** — ticket, SLA, category and agent metrics
  computed on demand, with role-scoped visibility.
- **Audit logging** — an append-only trail across authentication, ticket
  changes, assignment changes and permission denials, with structural
  redaction and an Administrator-only reader.
- **AI ticket assistant** — optional and off by default; when enabled, it
  can suggest triage, a draft reply, or a resolution summary, but can
  never write to a ticket by itself.
- **Security & auth** — Argon2id password hashing, rotating httpOnly
  refresh tokens with reuse/theft detection, default-deny route
  protection, fixed-role RBAC, and rate limiting on the credential
  endpoints.
- **Testing** — 864 backend unit tests (44 suites), 350 backend e2e tests
  (12 suites) against a real local PostgreSQL database, 481 frontend
  unit/component tests (39 files), and 11 Playwright end-to-end tests —
  all green as of this release.
- **Docker & CI** — multi-stage container images for both halves plus a
  full-stack Compose run, and a five-job GitHub Actions pipeline
  (frontend, backend, browser e2e, dependency audit, image builds).
- **Documentation** — architecture and database ER diagrams, an API
  conventions guide, a decisions summary indexing 27 ADRs, and
  interview/demo material, alongside the full `DECISIONS.md` record.

## What's not included

- **Not deployed anywhere.** No hosting account, managed database,
  registry, domain or credential exists. `docs/deployment.md` lists the
  external steps a real deployment would need.
- **Container images**: written and statically checked, first actually
  built by this release's CI run (Docker was never installed on the
  authoring machine).
- **Staff-visible user directory**: `GET /users` is Administrator-only, so
  assignment UIs across the app are limited to "assign to me"-style
  actions rather than a picker — a single, consistently-deferred gap
  tracked in `TASKS.md`.
- Smaller, individually tracked deferrals are listed per phase in
  `TASKS.md` and are not repeated here.
